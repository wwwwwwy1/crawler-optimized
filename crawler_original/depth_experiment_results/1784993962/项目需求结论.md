# MAX_DEPTH 实验项目需求结论

## 结论

在当前原版遍历实现和相同约 10 分钟时间预算下，应选择：

```text
MAX_DEPTH = 1
```

不建议只把 `MAX_DEPTH` 提高到 3 后直接投入采集。

Depth 3 确实到达了第 3 层，但它把大量时间消耗在少数详情页链路、返回和
重启上，导致单位时间截图产出、近重复过滤后产出和横向页面覆盖都明显下降。

## 项目核心指标

| 指标 | Depth 1 中位数 | Depth 3 中位数 | Depth 3 相对变化 | 结论 |
|---|---:|---:|---:|---|
| 运行时间 | 583.0 秒 | 585.3 秒 | +0.4% | 时间基本相同，可直接比较 |
| 原始截图 | 85 | 37 | -56.5% | Depth 1 更好 |
| 截图/小时 | 524.8 | 227.5 | -56.7% | Depth 1 更好 |
| SHA-256 唯一图/小时 | 487.8 | 227.5 | -53.4% | Depth 1 更好 |
| dHash 去近重后图片/小时 | 438.4 | 209.1 | -52.3% | Depth 1 更好 |
| 动作/截图 | 1.59 | 3.45 | +117.5% | Depth 3 成本更高 |
| 唯一 Activity | 20 | 9 | -55.0% | Depth 1 横向覆盖更广 |
| dHash 近重复占比 | 17.2% | 8.1% | -9.1 个百分点 | Depth 3 较好，但两者都不达标 |
| 详情页占截图比例 | 5.7% | 43.2% | +37.5 个百分点 | Depth 3 陷入详情页链 |
| 返回首页失败/重启 | 每轮 0 次 | 10、9、3 次 | 明显增加 | Depth 1 更稳定 |

`dHash 去近重后图片/小时` 是根据本次 Demo 的 dHash 阈值计算的代理指标，
不是经过人工标注的最终验收有效图/小时。

## 为什么 Depth 3 反而更差

Depth 3 三次都真实到达了第 3 层：

```text
max_depth_invoked = 3
```

因此结果不是参数未生效。

但是 Depth 3 中位数只有 9 个 Activity，并且约 43.2% 的截图来自
`UnitedBizDetailsActivity`。日志显示它在少数详情页分支持续深入，并多次
出现“返回首页失败，重启 App”：

```text
第 1 轮：10 次
第 2 轮：9 次
第 3 轮：3 次
```

同样的时间内，Depth 1 主要进行横向探索，覆盖约 20 个 Activity，三轮截图
分别为 85、87、85，结果稳定。

这说明当前原版采用深度优先递归时，单纯提高深度会产生两个问题：

1. 深层分支占用时间，首页其他 Tab 和入口没有机会被探索；
2. 返回路径越长，回退失败和重启成本越高。

## 与项目需求的对应关系

项目最终关注：

- App 端 400 万张有效截图；
- 最终有效截图/设备小时；
- 最终有效率至少 90%；
- 近重复率不超过 3%；
- 页面和品类覆盖；
- 采集稳定性和可恢复性。

按本次数据：

### 产出效率

Depth 1 的 dHash 去近重后候选约为 438.4 张/小时，Depth 3 约为
209.1 张/小时。Depth 1 是 Depth 3 的约 2.1 倍。

### 覆盖

Depth 1 覆盖约 20 个 Activity，Depth 3 只有 9 个。Activity 不是完整的 UI
状态指标，但可以作为当前原版的覆盖代理，说明 Depth 3 的横向覆盖明显更差。

### 重复率

Depth 3 的 dHash 近重复占比 8.1%，优于 Depth 1 的 17.2%。但需求目标是
不超过 3%，而且固定 dHash 阈值未经人工样本校准，所以两个版本都不能据此
声称达到去重验收要求。

### 最终有效率

本实验没有对加载页、弹窗、隐私、设计感、分类和业务有效性进行人工标注，
因此不能计算需求口径的最终有效率，也不能证明达到 90%。

## 决策

当前阶段：

```text
保留 MAX_DEPTH=1 作为原版生产基线。
```

下一步不应直接测试 Depth 5 或 Depth 8，而应先增加：

1. `template_id`：识别视频详情等重复模板；
2. 同模板连续深入上限：详情 A 可以进入详情 B，但 B 不再点击推荐视频；
3. 动作类型限制：停止推荐视频链，但允许评论、UP 主、选集等不同模板；
4. 父状态恢复校验：返回失败立即结束该分支；
5. Best-First 或宽度预算：先覆盖首页不同入口，再把剩余预算用于深层状态。

完成上述控制后，再比较：

```text
Depth 1
vs
Depth 3 + 同模板限制 + 父状态恢复
```

只有后者的“人工确认有效且不重复图片/设备小时”超过 Depth 1，才应提高默认
深度。
